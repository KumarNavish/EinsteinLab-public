## Provider choice, consent and privacy

The user authorized temporary `gpt-live-1`, with `gpt-6.1-sol` reasoning,
research and image inspection. The 16 October authenticated model catalogue found
Live 1, Live Transcribe and Sol, with no Live 1.1. The
[15 October announcement](https://community.openai.com/t/gpt-live-1-1-is-rolling-out-with-new-voices-and-better-accents/1406704)
and [staff follow-up](https://community.openai.com/t/gpt-live-1-1-is-rolling-out-with-new-voices-and-better-accents/1406704/6)
then said Live 1.1 API access was forthcoming; the
[product release note](https://openai.com/products/release-notes/) describes its
ChatGPT rollout. The deployed and publicly exercised model is Live 1. A future
upgrade needs verified API availability, explicit configuration and fresh acceptance.

The existing Gemini local route is preserved. Its nonbillable-project proof did
not permit a free public route for the intended Swiss/EEA/UK audience under
[Google's current API terms](https://ai.google.dev/gemini-api/terms).
Public Google inference remains disabled. OpenAI is the explicitly authorized
public provider; there is no automatic provider fallback.

Live handles continuous full-duplex conversation; Sol receives detailed reasoning
and tool instructions. Only existing bounded functions are exposed. Pages,
frames, diagram renders, source-region IDs and browser acknowledgements retain
their original ownership gates. Images reach a vision-capable backend; Live does
not inspect pixels directly. Live has no per-turn completion/interruption event:
backend completion is not speech completion. Ordinary barge-in manages local
playback while backend work continues; Stop closes the whole session.
[Live model](https://developers.openai.com/api/docs/models/gpt-live-1),
[delegation](https://developers.openai.com/api/docs/guides/live-delegation),
[session semantics](https://developers.openai.com/api/docs/guides/live-conversations).

Official lab lookup uses accessible official pages with a labelled dated snapshot
when live retrieval fails. Separately consented public search/read now uses
**OpenAI Responses web search with GPT-6.1 Sol** under the existing funded project.
The actual current public protocol searched once and opened the returned official
VR for Relaxation URL once, then narrated a cautious source-grounded answer.
Returned text is labelled as a cited provider-grounded summary. It is not a
verbatim page extract, image/layout inspection or independent verification.

Each operation makes one bounded Responses request, with at most one search
action or three exact-URL page opens. A read counts only with actual retrieved
content, an exact completed open and a matching citation; unavailable pages are
reported as unavailable. Queries and public URLs go to OpenAI only after Settings
approval; keep private documents, credentials and account details out of queries.
There is no login, paywall/anti-bot bypass, automatic provider fallback or new
hosting plan. The older keyless Exa path failed its hosted acceptance and is not
the deployed OpenAI public research route.

The app saves no microphone audio or transcripts. `session.store=false` disables
optional Live recording/forking; it does not disable provider monitoring. OpenAI
normally retains abuse-monitoring content for up to 30 days; delegated Responses
may retain backend state under its own data controls. No zero-retention approval
or regional-processing guarantee is claimed. Visitors must approve processing
before capture, and selected pages/frames need separate approval. Removing or
replacing material revokes its existing IDs. Do not send confidential material.
[Provider retention](https://developers.openai.com/api/docs/guides/your-data).

## Rebuild, verify and deploy

Use [the locked CI tools](../deploy/ci-tools/README.md) and
[allowlisted bundle builder](../deploy/fastapicloud/README.md). The workflow
reproduces both pinned private release inputs and the reviewed native closure on
GitHub's Linux runner; no running Mac, tunnel or local model is needed.

1. Merge reviewed source into `main`; select its exact lowercase 40-character
   SHA. Require a successful completed push/manual quality run for that SHA.
   A PR-only run or a skipped docs-only change is insufficient: dispatch quality
   checks explicitly when needed and verify `headSha`.
2. Dispatch the manual deployment workflow from `main`:

   ```sh
   gh workflow run manual-deploy.yml --repo KumarNavish/EinsteinLab --ref main \
     -f commit=EXACT_40_CHARACTER_MERGED_COMMIT_SHA
   ```

3. Inspect commit, manifest and sanitized deployment ID. CLI JSON mode confirms
   submission; read actual host terminal/build state before visitor acceptance.
   Inspect an interrupted submission before retrying.
4. Keep provider configuration and secrets in the host store: `EINSTEIN_PROVIDER=openai`,
   `OPENAI_API_KEY` and `EINSTEIN_OPENAI_APPROVAL`, plus existing exact origin,
   asset-publication approval and private feedback relay settings. Never put a
   provider key in GitHub, browser code, logs or artifacts. Secret flags and the
   deployed runtime are verified separately; never print secret values while
   checking configuration. Keychain remains the operator's secure local copy.
5. Complete the separately authorized, bounded public protocol in
   [qa/public-acceptance](../qa/public-acceptance/README.md). Check actual speech,
   interruption, paper/slide/video pixels and model annotations, diagrams,
   grounded discussion, concurrent visitors, closure and usage. Do not infer
   those from offline tests or model-list access. Before paying for another full
   protocol, require successful actual Linux conversion of its unchanged two-slide
   chart fixture and repeat that conversion on the public image. Run the release
   gate last. On a fresh ordinary UTC day, run the full protocol first. Its two
   accepted provider sessions leave room for the auxiliary protocol's two starts
   (initial plus manual reconnect) within the four-per-network/day allowance.
   Every successful diagnostic start also consumes that allowance. If a focused
   microphone run is needed first, defer another allocation to a later ordinary
   day; do not assume full + microphone + auxiliary fits in four starts. No
   automatic retry, counter reset, deployment reset, network change or limit
   increase is part of validation. The tested network's next ordinary reset is
   **18 October 2026 at 00:00 UTC**. This is planning guidance, not a scheduled run.
